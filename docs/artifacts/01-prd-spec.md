## C. 필수 화면 (PRD 5절이 명시한 것)

PRD 5절 서두: "**최소 2개**를 만들어주세요. 여유가 있다면 더 만드셔도 좋지만,
아래 두 개를 먼저 완성한 뒤에 진행해주세요."
→ **2개는 하한선이자 우선순위 1순위다. 확정 개수가 아니다.** (개수 계산은 ③단계 일)

### C-1. `New/Home` (PRD 5-1)

| 항목 | 내용 (원문 그대로) |
|---|---|
| 목적 | "서로 다른 이유로 들어온 사용자가 각자 자기 다음 행동을 바로 찾는다." |

| # | 필수 요소 | 원문 |
|---|---|---|
| H1 | 항공권 검색 진입 | "**항공권 검색 진입** — 출발지·목적지·날짜·인원" |
| H2 | 예정된 여정 | "**예정된 여정** — 출발까지 남은 기간, 그리고 그 목적지에서 살 수 있는 **투어·체험·입장권** 제안" |
| H3 | 둘러보기 묶음 | "**둘러보기 묶음** — 특가 항공권과 여행 상품을 여러 갈래로 소개하는 영역. 갈래는 직접 정해주세요 (테마 · 할인율 · 마감 임박 · 땡처리 등)" |
| H4 | 담아둔 목적지 | "**담아둔 목적지** — 값이 떨어지면 알림을 받기 위해 담아두는 곳" |
| H5 | 하단 주요 이동 수단 | "하단 주요 이동 수단" |

- H3의 "갈래"는 **PRD가 설계자에게 위임한 자유 항목**이다. 예시로 든 4가지(테마/할인율/마감 임박/땡처리)는 선택지이지 강제 목록이 아니다. ③단계가 정한다.

### C-2. `New/Results` (PRD 5-2)

| 항목 | 내용 (원문 그대로) |
|---|---|
| 목적 | "수십 건 중에서 나에게 맞는 한 편을 골라 결정까지 간다." |

| # | 필수 요소 | 원문 |
|---|---|---|
| R1 | 항공편 목록 | "**항공편 목록** — 출발·도착 시각, 소요 시간, 경유 여부, 항공사, 가격" |
| R2 | 경유 구간 표현 | "**경유 구간 표현** — 경유가 있는 편은 어디서 얼마나 기다리는지 알 수 있게" |
| R3 | 출발일 앞뒤 가격 비교 | "**출발일 앞뒤 가격 비교** — 며칠 전후로 옮기면 얼마인지" |
| R4 | 조건 좁히기 | "**조건 좁히기** — 직항 여부·시간대·항공사 등" |
| R5 | 비교함 | "**비교함** — 항공편을 담고, 담긴 것들을 나란히 보는 진입점" |
| R6 | 운임 등급 선택 | "**운임 등급 선택** — 같은 항공편이라도 환불·변경·수하물 조건이 다른 여러 운임 **(별도 화면이 아니라 이 화면 위에 올라오는 형태로 만들어주세요)**" |

### 🔴 C-3. R6 제약 — 절대 위반 금지

**운임 등급 선택은 `New/Results`와 별개의 최상위 프레임으로 만들면 안 된다.**
PRD 원문: "(별도 화면이 아니라 **이 화면 위에 올라오는 형태로** 만들어주세요)"

- 허용: `New/Results` 화면 위에 겹쳐 올라온 바텀시트/모달 형태.
  즉 `New/Results`를 복제한 상태 변형 프레임(예: `New/Results-FareSelect`) 안에서
  **뒤에 Results 내용이 보이고 그 위에 시트가 얹힌** 구성.
- 금지: 운임 등급만 단독으로 들어 있는 빈 배경 프레임.
- ⑥단계 참고: 뒤 화면을 어둡게 할 때 반투명 스크림을 덮지 말고
  **뒤 콘텐츠 보드의 `opacity`를 낮춘다** (AGENTS.md 알려진 함정).

- R5 "비교함 … 담긴 것들을 **나란히 보는 진입점**"은 진입점이므로 **목적지가 존재해야 한다.**
  ③단계가 이를 화면으로 환원한다.
- R4 "조건 좁히기"는 진입점이 눌렸을 때의 결과가 필요하다. ③단계 판단.

## D. 유저 스토리 분해 (③단계 입력)

PRD 3절. 각 스토리를 "하려는 것 / 확인하려는 것"으로 분해했다.
**확인하려는 것은 그 자체로 화면 후보다.**

| # | 스토리 원문 | 사용자가 하려는 것 | 확인하려는 것 |
|---|---|---|---|
| S1 | "**앱을 연 사용자로서**, 지금 나에게 필요한 것부터 바로 시작하고 싶다." | 진입 직후 자기 목적에 맞는 다음 행동을 시작 | 3종 페르소나 각각의 시작점이 한 화면에 동시에 보이는 상태 |
| S1-a | (3절-1 하위) "날짜와 목적지가 이미 정해져 검색만 하면 되는 사용자" | 출발지·목적지·날짜·인원을 넣고 검색 | 검색 결과 |
| S1-b | (3절-1 하위) "어디로 갈지 못 정한 채 싼 표를 구경하러 오는 사용자" | 목적지 미정 상태로 싼 표 탐색 | 특가/할인 묶음, 그 안의 개별 상품 |
| S1-c | (3절-1 하위) "이미 표를 끊어두고 현지에서 할 것을 찾으러 오는 사용자" | 예정된 여정 확인 후 현지 상품 탐색 | 남은 기간 + 그 목적지의 투어·체험·입장권 |
| S2 | "**지금 당장 살 생각은 없는 사용자로서**, 마음에 둔 목적지를 담아두고 값이 떨어지면 알림을 받고 싶다." | 목적지를 담는다 / 가격 알림을 켠다 | ①담아둔 목록 ②**값이 떨어졌다는 알림·가격 변동 결과** |
| S3 | "**결정을 앞둔 사용자로서**, 조건이 비슷한 항공권 몇 개를 담아 나란히 비교하고 싶다." | 항공편 여러 개를 비교함에 담는다 | **나란히 놓인 비교 결과** (담는 동작과 비교 확인은 별개 화면 후보) |

### D-1. ③단계에 남기는 판정 재료

- S2의 "값이 떨어지면 알림을 받고 싶다" → 담는 UI만으로는 스토리가 닫히지 않는다. 가격 하락을 **확인**하는 표현이 어딘가에 있어야 한다.
- S3의 "나란히 비교하고 싶다" → C-2 R5의 "진입점"과 짝이다. 진입점만 있고 나란히 보는 결과가 없으면 S3이 미해결이다.
- S1-c → C-1 H2와 짝. 홈에서 시작하지만 "그 목적지에서 살 수 있는 투어·체험·입장권"의 목적지가 필요한지 ③이 판단한다.
