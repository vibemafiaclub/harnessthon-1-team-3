# 01 — PRD 명세

> 입력: `docs/PRD.md` (제목: "[디자인 과제] 관심종목을 담고 매수까지 가는 경험을 설계해주세요")
> 이 문서는 PRD 산문을 뒤 단계가 기계적으로 소비할 수 있는 표로 환원한 것이다.
> 모든 행에 PRD 원문 근거가 붙어 있다. 근거 없는 값은 없다.

## A. 제품 정의

| 항목 | 값 | 근거 (PRD 인용) |
|---|---|---|
| 도메인 | 증권(주식 투자) 모바일 앱 — 관심종목 담기부터 매수 주문까지 | §1 "당근마켓을 만든 팀이 **증권 서비스**를 준비하고 있습니다." |
| 모(母)제품 / 톤 출처 | 당근마켓 (중고거래 앱) | §1 "당근마켓을 만든 팀이", "동네 이웃과 중고거래하듯" |
| 대상 사용자 | 주식을 처음 시작하는 사람(투자 초보) | §1 "주식을 처음 시작하는 사람이 대상입니다." / §3-1 "**투자를 처음 하는 사용자로서**" |
| 해결하려는 문제 | 기존 증권 앱의 정보 과밀로 인한 첫 화면 이탈 | §1 "기존 증권 앱은 화면 하나에 숫자가 수십 개씩 들어가 있어서, 무엇을 봐야 할지 모르는 사람은 첫 화면에서 이탈합니다." |
| 핵심 목표 | 부담 없고 익숙한 경험으로 주식을 접하게 하기 | §1 "동네 이웃과 중고거래하듯 **부담 없고 익숙한 경험**으로 주식을 접하게 하는 것이 목표입니다." |
| 최대 이탈 지점 | "무엇을 살지 못 정한" 상태 / 관심종목이 빈 상태 | §3-4 "→ 이게 가장 큰 이탈 지점입니다. 관심종목이 비어 있으면 아무것도 시작되지 않습니다." |
| 최종 산출물 성격 | 그림이 아니라 AI가 이어서 작업 가능한 데이터로서의 디자인 | 평가 절 "저희가 최종적으로 보는 것은 **보기 좋은 그림**이 아니라 **AI 에이전트가 읽고 이어서 작업할 수 있는 데이터로서의 디자인**입니다." |

### A-4. 선호 테마 (§4-3 — 원문 그대로)

`반도체` · `항공우주` · `방산` · `2차전지` · `바이오`

> 근거: §4-3 "**반도체 · 항공우주 · 방산 · 2차전지 · 바이오** 처럼 특정 테마만 보는 사용자가 많습니다."
> 요구: "어떤 테마가 요즘 오르는지"와 "그 테마에 뭐가 들어 있는지"를 **둘 다** 알고 싶어 함.

### A-5. 판단에 영향을 주는 정보 (§4-1 — 원문 표 그대로)

| 정보 | 예 (PRD 원문) |
|---|---|
| 시장 호재·악재 | "미국 반도체 수출 규제 완화", "환율 급등" |
| 전문가 매수/매도 의견 | 증권사 컨센서스 — 매수 12 · 중립 3 · 매도 1, 목표주가 |
| 실적 발표 | 다음 주 실적 발표 예정 종목, 어제 발표한 종목의 서프라이즈 여부 |
| 수급·거래량 | 외국인·기관이 오늘 많이 산 종목 |

> §4 총괄 지시: "위 세 가지(정보·스타일·테마)를 **사용자가 직접 고르게 하고, 그 선택이 추천에 실제로 반영되는 것처럼 보이게** 만들어주세요. 추천 결과가 왜 나왔는지 설명이 붙어야 합니다."
> → 이 문장은 ③단계에 **선택 UI(스타일/테마 설정) 화면 후보**와 **추천 사유 표기 규칙**을 동시에 넘긴다.

## B. 기존 자산 (②단계가 읽을 대상)

| 항목 | 값 | 근거 |
|---|---|---|
| 파일 | 우리 조의 **`작업`** 파일 (같은 파일 안의 Page로 존재) | §2 "Penpot 파일: 여러분 조의 **`작업`** 파일" |
| **읽을 Page 이름** | **`1-daangn`** | §2 "읽을 대상: **`1-daangn` Page** — 화면 5개가 들어 있습니다" |
| **읽지 말 Page 이름** | **`2-airbnb`** | §2 "⚠️ 같은 파일에 **`2-airbnb` Page**도 있습니다. 그건 **다른 과제의 기존 파일**이니 이 과제에서는 **`1-daangn`만** 읽어주세요." |
| 기존 화면 개수 | 5개 | §2 "화면 5개가 들어 있습니다" |
| 기존 화면 이름 | 홈 피드 · 상품 상세 · 나의 당근(프로필·메뉴) · 채팅 목록 · 롱스크롤 화면 | §2 해당 줄 원문 |
| 디자인 시스템 문서 유무 | **없음** — 이 Page가 전부 | §2 "이 Page가 저희가 가진 전부입니다. 별도의 디자인 시스템 문서나 컴포넌트 정리본은 없습니다." |
| `1-daangn` 쓰기 권한 | **읽기 전용** | §8 "(`1-daangn`은 읽기 전용입니다)" |

### B-2. 실측 Page 목록과의 매칭

파일에 실존하는 Page 10개: `1-daangn`, `2-airbnb`, `김주철`, `고지원`, `김나연`, `김혜령`, `박구용`, `이동은`, `중간공유`, `최종제출`

| PRD가 지정한 이름 | 실측 Page | 매칭 |
|---|---|---|
| `1-daangn` (읽을 대상) | `1-daangn` | ✅ 정확히 일치 |
| `2-airbnb` (읽지 말 것) | `2-airbnb` | ✅ 정확히 일치 |

- ②단계는 **`1-daangn`만** 읽는다. `2-airbnb`를 열지 않는다.
- 읽기 전용이므로 **Page 전환 없이** 읽는 방법을 택한다 (`penpot.currentFile.pages` 순회).
- 저작 대상 Page는 PRD가 정하지 않고 "본인 이름 Page"라고만 한다 (§8) → 이번 실행 인자는 `김주철`.

## C. 필수 화면 (PRD §6이 명시한 것 — 하한선)

> §6 "**최소 3개**를 만들어주세요. 아래 순서대로 완성해주세요. 여유가 있다면 3절·5절에서 요구되는 화면을 더 만들어주셔도 좋습니다."
> → **3개는 하한선이지 확정 개수가 아니다.** 최종 화면 목록 계산은 ③단계의 일이다.

| # | 프레임 이름 | 목적 (원문) | 필수 요소 (원문 그대로) |
|---|---|---|---|
| 1 | `New/Watchlist` | "사용자가 담아둔 종목의 현재가와 등락을 한 화면에서 훑는다." | • 종목 목록 — 종목명, 현재가, 등락률<br>• 상승/하락의 시각적 구분<br>• 정렬 또는 필터 진입점 |
| 2 | `New/StockDetail` | "종목 하나를 판단하고, 그 자리에서 주문까지 끝낸다." | • **가격 차트** — 기간 전환(1일/1주/1개월 등) 포함<br>• 현재가와 등락 정보<br>• 종목 기본 정보<br>• **매수 / 매도 주문 진입** — 하단 고정 액션<br>• **주문 시트** — 수량·가격 입력, 예상 금액, 주문 확정 (별도 화면이 아니라 이 화면 위에 올라오는 형태) |
| 3 | `New/Discover` | "무엇을 살지 못 정한 사용자가 **오늘 살 만한 것**을 찾는다." | • **내 투자 스타일 기반 추천** — 추천 이유가 한 줄로 붙어야 함 (예: "변동성 선호 · 오늘 3.2% 움직임")<br>• **오늘의 시장 이슈** — 호재/악재와 그로 인해 움직인 종목의 연결<br>• **전문가 의견** — 매수/중립/매도 분포와 목표주가<br>• **실적 발표 일정** — 곧 발표할 종목<br>• **테마** — 테마별 등락과 진입점<br>• 투자 스타일이 아직 없는 사용자를 위한 **설정 진입점** |

### C-2. 필수 요소에 붙은 부가 지시

|---|---|---|

## D. 유저 스토리 분해 (③단계 입력)

> "…하고 **그 결과를 확인**하고 싶다" 형태는 **동작**과 **확인**이 각각 화면 후보다.
> 아래는 재료만 남긴 것이며, 화면 확정은 ③이 한다.

| # | 스토리 원문 | 사용자가 하려는 것 (동작) | 확인하려는 것 (결과) |
|---|---|---|---|
| S1 | "**투자를 처음 하는 사용자로서**, 관심 있는 종목을 모아두고 등락을 한눈에 확인하고 싶다." | 관심 종목을 **모아둔다** (담기 / 추가) | 모아둔 종목의 **등락을 한눈에** 본다 |
| S2 | "**매수를 고민 중인 사용자로서**, 종목의 가격 흐름과 기본 정보를 보고 판단하고 싶다." | 종목 하나를 열어 **가격 흐름과 기본 정보**를 본다 | 매수 여부를 **판단**한다 |
| S2b | "어떤 사용자는 등락률을, 어떤 사용자는 내 수익률을, 어떤 사용자는 거래량을 먼저 봅니다." | 무엇을 먼저 볼지 **바꾼다** (지표 전환 / 정렬 기준 선택) | 등락률 / **내 수익률** / 거래량 — 3종 지표 |
| S3 | "**매수를 결정한 사용자로서**, 수량과 가격을 입력해 주문하고 그 결과를 확인하고 싶다." | 수량·가격을 **입력해 주문**한다 (주문 시트) | 주문의 **결과를 확인**한다 (주문 완료/체결 결과) |
| S4 | "**무엇을 살지 아직 못 정한 사용자로서**, 지금 살 만한 종목을 찾고 싶다." | 지금 살 만한 종목을 **찾는다** (발견) | 왜 추천됐는지 (§4 "추천 결과가 왜 나왔는지 설명이 붙어야 합니다") |
| S4b | "→ 이게 가장 큰 이탈 지점입니다. 관심종목이 비어 있으면 아무것도 시작되지 않습니다." | 빈 관심종목에서 **시작한다** | 빈 상태에서 다음 행동으로 넘어가는 경로 |
| S5 | §4 총괄: "세 가지(정보·스타일·테마)를 **사용자가 직접 고르게 하고**" | 정보 유형 / 투자 스타일 / 테마를 **직접 고른다** | 그 선택이 **추천에 반영된** 결과 |
| S6 | §4-3: "'어떤 테마가 요즘 오르는지'와 '그 테마에 뭐가 들어 있는지'를 둘 다 알고 싶어 합니다." | 테마를 **연다** (테마 진입점 → 목적지) | 테마별 등락 + 테마 구성 종목 |

### D-2. 명시적 "진입점" 문구 목록 (진입점은 목적지를 요구한다)

| 진입점 원문 | 출처 |
|---|---|
| "정렬 또는 필터 **진입점**" | §6-1 |
| "**매수 / 매도 주문 진입** — 하단 고정 액션" | §6-2 |
| "테마 — 테마별 등락과 **진입점**" | §6-3 |
