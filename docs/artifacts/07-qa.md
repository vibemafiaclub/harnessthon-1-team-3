## F. 이 단계에서 실측한 환경 함정 (다음 실행 필독)

④·⑤·⑥ 문서에 없던 것들이다. 전부 직접 부딪혔다.

1. **🔴 컴포넌트 메인 인스턴스는 새 자식을 받지 않는다.**
   `appendChild`·`insertChild` 모두 **에러 없이 "성공"을 반환하고 조용히 무시**한다.
   → **컴포넌트 원본을 고쳐 인스턴스에 전파하는 전략은 불가능하다.** 화면별로 처리해야 한다.
   (오케스트레이터 지시의 "컴포넌트 원본을 고치면 전파된다"는 이 환경에서 성립하지 않았다.)

2. **🔴 `createShapeFromSvg`는 만든 그룹을 임의의 보드에 자동 부착한다.**
   `penpot.selection`을 미리 지정해도 바뀌지 않는다. 이 파일에서는 항상
   `New/Home`의 `StatusBar` 인스턴스로 갔고, **그 보드 밖 좌표로 이동시키면 좌표가 무시된다.**

3. **🔑 그러나 `clone()`한 그룹은 임의 좌표로 자유롭게 이동한다.**
   → **아이콘을 화면마다 새로 만들지 말고, 검증된 아이콘 1벌을 만들어 `clone()`으로 전파하라.**
   이번 단계의 A 결함은 전부 이 방법으로 해결했다.

4. **🔴 flex 자식을 `hidden`으로 감추면 부모가 붕괴한다.**
   `TabItem`이 h36 → h12로 줄고 **라벨이 아이콘 위치로 올라와 겹쳤다.**
   → 자리를 유지해야 하면 `hidden` 대신 **`fills = []`(투명)** 을 쓴다.

5. **🔴 구조 조회(`type === "rectangle"`)만으로 placeholder를 판정하지 마라.**
   B·C 결함은 **실제로는 이미 해결되어 있었는데** 구조만 보고 "회색 네모/빈 원"으로 오판된 것이다.
   투명 rect 위에 진짜 아이콘이 얹혀 있는 구조였다.
   → **⑦의 판정 근거는 반드시 PNG여야 한다.** 이 단계 지침의 원칙이 실제로 옳았다.

6. `remove()`도 컴포넌트 인스턴스의 자식에 대해서는 **성공을 반환하고 실패**한다.
   지워졌는지 반드시 **재조회로 확인**하라.
