# ② 기존 파일 디자인 실측

PRD는 "기존 디자인의 톤앤매너를 유지하라"고 요구한다.
**AI는 놔두면 자기 취향의 색을 쓴다.** 그래서 이 단계는 추정하지 않고 **실측한다.**

이 단계는 **읽기 전용이다.** 아무것도 만들지 않고 아무것도 고치지 않는다.

## 입력 (이것만 읽는다)

- `docs/artifacts/01-prd-spec.md`
- Penpot — `01-prd-spec.md` B절이 지정한 **기존 자산 Page** (읽기 전용)

## 출력 (이것만 쓴다)

- `docs/artifacts/02-design-audit.md`

## 🔴 Page 규칙 (어기면 남의 작업을 망친다)

- **읽기만 할 때는 Page를 전환하지 않는다.** 전환하면 협업 중인 다른 사람이 보는
  화면도 같이 바뀐다. `penpot.currentFile.pages`로 **노드를 직접 순회**해 읽는다.
- 기존 자산 Page는 **읽기 전용이다.** 수정·이동·삭제 금지.
- Page 이름을 **하드코딩하지 않는다.** `01-prd-spec.md` B절의 값을 쓴다.
- B절이 지정한 Page를 파일에서 못 찾으면 **즉시 중단하고 보고한다.**
  이름이 비슷한 다른 Page를 임의로 고르지 않는다.

## 절차

1. `01-prd-spec.md`를 읽는다. 없으면 **즉시 중단하고 보고한다.**

2. B절에서 **읽을 Page 이름**과 **읽지 말 Page 이름**을 확보한다.

3. `penpot.currentFile.pages`로 실제 Page 목록을 가져와 이름을 **매칭**한다.
   PRD가 적은 이름과 실제 파일의 이름이 다를 수 있다. 정확히 일치하는 것이 없으면
   후보 목록을 사용자에게 보여주고 **묻는다.** 추측해서 고르지 않는다.

4. 대상 Page의 노드 트리를 순회해 아래를 **수집한다.** 눈대중이 아니라 값을 읽는다.

   | 수집 대상 | 읽을 속성 |
   |---|---|
   | 색상 | 모든 `fills`의 `fillColor`, `fillOpacity`, 그리고 `strokes` |
   | 텍스트 | `fontFamily`, `fontSize`, `fontWeight`, `lineHeight`, `letterSpacing` |
   | 간격 | 오토레이아웃 프레임의 padding·gap, 형제 노드 간 실제 좌표 차 |
   | 모서리 | `borderRadius` (사각형·버튼·카드·이미지) |
   | 크기 | 화면 프레임의 width/height, 터치 타깃 높이 |
   | 그림자 | `shadows` |

5. **빈도로 정렬한다.** 가장 많이 쓰인 값이 그 제품의 규칙이다.
   1~2회만 등장한 값은 예외로 표시하고 토큰 후보에서 뺀다.

6. **반복 컴포넌트 패턴을 찾는다.** 같은 구조가 3회 이상 반복되면 기록한다.
   (리스트 행, 카드, 버튼, 탭바, 헤더, 뱃지 등 — 이름은 실제 구조를 보고 붙인다.)
   각 패턴의 **내부 구성과 가변 요소**를 적는다. ⑤단계가 이걸 만든다.

7. **폰트 가용성을 확인한다.** `penpot.fonts.all`로 실측한 폰트가 서버에 있는지 본다.
   없으면 **조용히 대체되어 에러 없이 다른 폰트로 그려진다.**
   없는 폰트는 대체 후보를 함께 적는다. ④가 결정한다.

8. 출력 파일을 쓴다. **모든 값에 "몇 번 나왔는지"를 적는다.**

## 출력 형식

```markdown
# 02 — 기존 디자인 실측

## 대상
| 항목 | 값 |
|---|---|
| 읽은 Page | `...` |
| 순회한 노드 수 | |
| 기존 화면 목록 | |

## A. 색상 (빈도순)
| HEX | 빈도 | 쓰인 곳 | 추정 역할 |
|---|---|---|---|

## B. 타이포 (빈도순)
| fontFamily | size | weight | lineHeight | 빈도 | 쓰인 곳 | 추정 역할 |
|---|---|---|---|---|---|---|

### 폰트 가용성
| 폰트 | 서버에 있나 | 대체 후보 |
|---|---|---|

## C. 간격 (빈도순)
| 값(px) | 빈도 | 종류(padding/gap) | 쓰인 곳 |
|---|---|---|---|

## D. 모서리 반경 (빈도순)
| 값(px) | 빈도 | 쓰인 곳 |
|---|---|---|

## E. 화면 규격
| 항목 | 값 |
|---|---|
| 화면 width | |
| 화면 height | |
| 좌우 기본 여백 | |
| 터치 타깃 최소 높이 | |

## F. 반복 컴포넌트 패턴
| 패턴 이름 | 반복 횟수 | 내부 구성 | 가변 요소 | 고정 요소 |

- (색·형태·여백에서 읽히는 성격을 문장으로. 예: 라운드가 크고 여백이 넉넉하다)

| 값 | 빈도 | 왜 예외인가 |
|---|---|---|
```

## 금지

- **값을 추정하지 않는다.** 읽지 못했으면 "읽지 못함"이라고 적는다. 그럴듯한 HEX를 지어내지 않는다.
- 기존 Page를 **수정하지 않는다.** 이 단계는 쓰기 작업이 없다.
- **읽기 목적으로 `openPage()`를 호출하지 않는다.**
- **특정 PRD 전용 하드코딩 금지.** Page 이름·색상값·컴포넌트 이름을 이 파일 지침에 박지 않는다.
  전부 `01-prd-spec.md`와 실측에서 온다.
- 다른 단계의 출력 파일을 쓰지 않는다.
