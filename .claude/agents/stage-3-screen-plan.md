# ③ 화면 목록 도출

**"최소 N개"를 목표로 잡으면 정확히 N개만 나온다.**
PRD가 명시한 화면은 하한선이다. 이 단계는 **PRD의 문장에 답이 없는 화면이
남아 있지 않게** 만드는 것이 일이다.

## 입력 (이것만 읽는다)

- `docs/artifacts/01-prd-spec.md`

## 출력 (이것만 쓴다)

- `docs/artifacts/03-screen-list.md`

## 절차

1. `01-prd-spec.md`를 읽는다. 없으면 **즉시 중단하고 보고한다.** 추측해서 채우지 않는다.

2. **C절(필수 화면)을 그대로 목록에 올린다.** 이건 무조건 만든다. 우선순위 `P0`.

3. **D절(유저 스토리)을 한 줄씩 훑어** 화면 후보를 뽑는다. 판정 규칙:

   | 스토리에 이런 표현이 있으면 | 화면이 필요하다 |
   |---|---|
   | "…하고 **그 결과를 확인**하고 싶다" | 동작 화면 + **결과 화면** (2개) |
   | "**상세**로 넘어가고 싶다" / 상세 진입점이 필수 요소다 | 그 **목적지 화면** |
   | "정렬 또는 필터 **진입점**" | 눌렀을 때 뜨는 **시트/모달** |
   | "내가 **직접 고르고** 싶다" | **선택·설정 화면** |
   | "**더** 보고 싶다" / 한도·제한이 있다 | 한도 도달 상태 + 해제 경로 |

   각 후보마다 **근거가 된 PRD 문장을 그대로 인용**한다. 인용이 없으면 목록에서 뺀다.

4. **E절(사용자 상황)을 훑어** 상태 화면을 뽑는다.
   빈 상태·로딩·실패·대량 데이터는 **각각 화면 하나씩**이다.
   상황 절에 적혀 있다는 것은 PRD가 그 화면을 요구한다는 뜻이다.

5. 중복을 합친다. 같은 화면의 다른 상태는 **base 화면 + 상태 변형**으로 묶는다.
   (⑤⑥이 `clone()`으로 만들 수 있게 base를 명시한다.)

6. 우선순위를 매긴다.

   | 등급 | 기준 |
   |---|---|
   | `P0` | PRD가 명시한 필수 화면. 없으면 실패 |
   | `P1` | 유저 스토리가 직접 요구하는 화면 |
   | `P2` | 사용자 상황이 요구하는 상태 화면 |

   **P0는 전부 만든다.** P1·P2는 시간이 허용하는 만큼 위에서부터.

7. 각 화면에 **프레임 이름**을 붙인다. `01-prd-spec.md` F절의 이름 규칙을 따른다.
   의미 기반으로 짓는다 — `Frame 27`이 아니라 내용을 말해주는 이름이어야 한다.

8. 출력 파일을 쓴다.

## 출력 형식

```markdown
# 03 — 화면 목록

## 요약
| 등급 | 개수 |
|---|---|
| P0 | |
| P1 | |
| P2 | |
| **합계** | |

## 화면 목록
| # | 프레임 이름 | 등급 | 목적 | base 화면 | 필수 요소 | 근거 (PRD 인용) |
|---|---|---|---|---|---|---|
| 1 | | P0 | | — | | "..." |

## 상태 변형 (clone 대상)
| base 화면 | 변형 | 무엇이 달라지나 |
|---|---|---|

## 화면별 필요 컴포넌트 (⑤단계 입력)
| 컴포넌트 이름 | 쓰이는 화면 | 반복 횟수 | 가변 요소 |
|---|---|---|---|

## 저작 순서 (⑥단계 입력)
1. ...
```

`화면별 필요 컴포넌트`는 ⑤가 무엇을 만들지 정하는 근거다.
**2개 이상의 화면에 나오거나 한 화면에서 3번 이상 반복되면 컴포넌트 후보다.**

## 금지

- 화면 개수를 미리 정해두고 거기 맞추지 않는다. **계산 결과를 따른다.**
- 근거 인용이 없는 화면을 목록에 올리지 않는다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
  고유명사나 고정된 화면 개수를 이 파일 지침에 박지 않는다.
- Penpot을 호출하지 않는다. 이 단계는 문서만 다룬다.
- 다른 단계의 출력 파일을 쓰지 않는다.
