# ⑦ 시각 검증

**자기 화면은 자기가 못 본다.** 그래서 이 단계는 교차 검토다.
⑥을 저작한 사람이 아닌 사람이 돈다.

**이 단계는 화면을 고치지 않는다.** 무엇이 잘못됐는지 **찾아서 적는다.**
고치는 것은 ⑥ 담당이 `07-qa.md`를 읽고 한다.

## 입력 (이것만 읽는다)

- `docs/artifacts/03-screen-list.md` — 있어야 할 화면·필수 요소
- `docs/artifacts/06-screens.md` — 저작했다고 주장하는 것
- Penpot — 작업 Page (읽기 + `export_shape`)

## 출력 (이것만 쓴다)

- `docs/artifacts/07-qa.md`

## 🔴 Page 규칙

- 검토 대상 Page 이름을 **인자로 받는다.** 없으면 묻고 멈춘다.
- 이 단계는 **읽기 전용이다.** 노드를 고치지 않는다.
- `export_shape`가 **레이아웃 안정 전에 찍히면 빈 영역이 나온다.**
  → **"없다"고 판단하기 전에 반드시 재-export 한 번.** 이걸 빠뜨리면 오탐이 쏟아진다.

## 절차

1. 세 입력을 확보한다. `03`이나 `06`이 없으면 **즉시 중단하고 보고한다.**

2. `03`의 화면 목록과 Penpot의 실제 프레임을 **대조한다.**
   - 이름이 정확히 일치하는가
   - `03`에 있는데 Penpot에 없는 것 → **누락**
   - Penpot에 있는데 `03`에 없는 것 → **정체 확인** (실험 잔재일 수 있다)

3. 화면마다 `export_shape`로 PNG를 찍어 **실제로 본다.**
   빈 영역이 나오면 **재-export**하고, 그래도 비면 그때 누락으로 판정한다.

4. PNG를 보고 아래를 판정한다. **추측하지 말고 보이는 것을 적는다.**

   | 점검 항목 | 무엇을 보나 |
   |---|---|
   | **텍스트 잘림** | 글자 아래가 잘렸나. auto-height 재계산이 빠진 신호 |
   | **정렬** | 좌우 여백이 화면마다 같은가. 요소가 그리드에서 튀는가 |
   | **간격 일관성** | 같은 역할의 간격이 화면마다 다른가 |
   | **타이포 위계** | 제목과 본문이 구별되는가. 크기가 뒤집힌 곳은 없나 |
   | **색 조화** | 기존 톤에서 튀는 색이 있나. 대비가 부족해 안 읽히는 곳은 |
   | **빈 영역** | 의도치 않게 비어 있는 자리 |
   | **겹침** | 요소가 서로 덮고 있는 곳 |
   | **오버레이** | 반투명 스크림이 렌더링에서 사라졌나 |
   | **잘린 요소** | 프레임 밖으로 삐져나간 것 |

5. `03`의 **필수 요소**를 화면별로 대조한다. PRD가 요구한 요소가 화면에 **보이는가.**
   목록에만 있고 화면에 없으면 누락이다.

6. 노드 이름을 확인한다. `Frame 27` 같은 **의미 없는 이름이 남아 있으면 지적한다.**
   평가 기준에 "구조와 네이밍"이 있다.

7. **수정 지시를 구체적으로 적는다.** ⑥ 담당이 읽고 바로 고칠 수 있어야 한다.
   - ❌ "정렬이 이상함"
   - ✅ "`{화면}`의 `{요소}`가 좌측 여백 20인데 다른 화면은 16. 16으로 맞출 것"

8. 심각도를 매긴다.

   | 등급 | 기준 |
   |---|---|
   | `BLOCK` | P0 화면·필수 요소 누락. 이대로 제출 불가 |
   | `MAJOR` | 텍스트 잘림·겹침·정렬 붕괴. 완성도 점수를 직접 깎음 |
   | `MINOR` | 간격 미세 불일치·네이밍 |

9. 출력 파일을 쓴다.

## 출력 형식

```markdown
# 07 — 시각 검증

## 검토 정보
| 항목 | 값 |
|---|---|
| 검토 Page | `...` |
| 검토자 | (저작자와 달라야 한다) |
| 찍은 PNG 수 | |
| 재-export 횟수 | |

## A. 화면 대조
| `03`의 화면 | Penpot에 있나 | PNG 확인 | 판정 |
|---|---|---|---|

## B. 필수 요소 대조
| 화면 | 필수 요소 | 보이나 | 판정 |
|---|---|---|---|

## C. 발견 사항 (심각도순)
| # | 심각도 | 화면 | 무엇이 잘못됐나 | **수정 지시** |
|---|---|---|---|---|
| 1 | BLOCK | | | |

## D. 네이밍
| 화면 | 의미 없는 이름 | 제안 |
|---|---|---|

## E. 판정
| 항목 | 값 |
|---|---|
| BLOCK 건수 | |
| MAJOR 건수 | |
| MINOR 건수 | |
| **제출 가능한가** | (BLOCK이 0이어야 가능) |
```

## 금지

- **화면을 고치지 않는다.** 찾아서 적는 것까지가 이 단계다.
- **자기가 저작한 화면을 자기가 검토하지 않는다.** 교차 검토가 이 단계의 전제다.
- PNG를 보지 않고 판정하지 않는다. **본 것만 적는다.**
- 재-export 없이 "없다"고 판정하지 않는다. **오탐의 주범이다.**
- 추상적 지적 금지. **어느 화면 어느 요소를 어떻게 고칠지** 적는다.
- **특정 PRD 전용 하드코딩 금지.** 화면 이름·요소 이름을 이 파일 지침에 박지 않는다.
  전부 `03`에서 온다.
- 다른 단계의 출력 파일을 쓰지 않는다.
