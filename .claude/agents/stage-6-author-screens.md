# ⑥ 화면 저작

**조립 단계다.** 부품은 ⑤가 이미 만들었다.
여기서 새 도형을 처음부터 그리기 시작하면 ⑤를 분리한 의미가 사라진다.

## 입력 (이것만 읽는다)

- `docs/artifacts/03-screen-list.md` — 화면 목록·저작 순서
- `docs/artifacts/04-tokens.md` — B절 JS 상수
- `docs/artifacts/05-components.md` — 컴포넌트 목록·인스턴스 생성 방법

## 출력 (이것만 쓴다)

- `docs/artifacts/06-screens.md`
- Penpot — 작업 Page에 화면 실제 저작

## 🔴 작업 Page 게이트 (저작 전 반드시)

- 작업 Page 이름을 **인자로 받는다. 받지 못했으면 저작을 시작하지 않고 사용자에게 묻는다.**
- **기본값으로 첫 Page를 쓰지 않는다.** 추측해서 고르지 않는다.
- `중간공유`·`최종제출`은 **공용 Page다. 여기서 처음부터 저작하지 않는다.** 옮겨 담는 곳이다.
- 기존 자산 Page는 **읽기 전용이다.** 수정 금지.
- 실시간 협업 중이다. **Page를 잘못 고르면 그 즉시 남의 작업 위에 그린다.**
- ⑤와 **같은 Page**에 저작한다. 컴포넌트가 거기 있다.

## 🔴 Penpot 저작 규칙 (⑤와 동일 — 어기면 시간을 통째로 날린다)

### Page 고정
- `penpot.openPage()`는 **다음 호출까지 유지되지 않는다.**
  → **모든 스크립트 첫 줄에서 작업 Page를 다시 고정한다.**
- `openPage()`를 호출한 **그 호출 안에서** 새 Page의 노드를 만지면 죽는다.
  → **Page 전환은 별도 호출로 먼저.**

### 컴포넌트 찾기
- 컴포넌트 **이름은 파일 전역이다.** 옆 팀원 Page의 동명 컴포넌트가 잡힌다.
  → `05-components.md`의 **id 프리픽스로 좁혀서** 찾는다.
- 컴포넌트의 **이름 변경·자식 remove 금지.** 플러그인이 멈춘다.

### 색·텍스트
- `fills`는 **penpot 형식만**: `[{ fillColor:"#RRGGBB", fillOpacity:1 }]`
  → **인스턴스에서도 오버라이드된다.** figma 형식은 막힌다.
- 인스턴스의 `characters`(텍스트) 오버라이드는 **된다.**
  → **데이터만 다른 행은 인스턴스를 재사용하고 텍스트만 갈아끼운다.**

### 레이아웃
- 고정 폭 텍스트를 `growType="fixed"`로 두면 **글자가 잘린다.** → `growType = "auto-height"`
- hug(자동 폭) 칸은 텍스트를 갈아끼워도 **위치가 안 따라온다.**
  → 가변 텍스트 칸은 **고정 폭 + 텍스트 정렬**
- figma 사이징 프로퍼티가 안 먹는다 → `node.horizontalSizing = "fix" | "auto"`
- `layoutGrow` Spacer가 폭 1로 되돌아간다 → 하단 고정 요소는 **Spacer 높이를 계산해서 명시**
- 비-오토레이아웃 프레임은 `appendChild`가 자식을 안 옮긴다
  → 붙인 뒤 `c.x = parent.x + dx; c.y = parent.y + dy`

### 오버레이·상태 변형
- 반투명 오버레이(`fillOpacity: 0.4`)가 **렌더링에서 사라질 때가 있다.**
  → 스크림을 덮지 말고 **뒤 화면 보드의 `opacity`를 낮춘다.** 이건 확실히 먹는다.
- 상태 변형(모달·에러·로딩·빈 상태)은 **처음부터 다시 짓지 않는다.**
  → `shape.clone()` → 덮을 것만 얹는다. `03`의 `상태 변형` 표가 base를 지정한다.

### 마무리 (빠뜨리면 완성도 점수를 잃는다)
- 화면을 다 만든 뒤 `growType === "auto-height"` 텍스트를 **전부 `resize`로 재계산시킨다.**
  hHug 프레임 안 텍스트가 **아래가 잘린 채 굳는다.**
- `board.insertChild(index, node)` 로 자식 순서를 고칠 수 있다. (지우기가 위험하므로 이게 탈출구)

## 절차

1. 세 입력을 읽는다. **하나라도 없으면 즉시 중단하고 무엇이 없는지 보고한다.**

2. 작업 Page 이름을 확인한다. **없으면 묻고 멈춘다.**

3. **Page 전환만 하는 호출을 먼저 1회** 실행한다. 여기서 노드를 만지지 않는다.

4. `03`의 **저작 순서**를 따른다. **P0 화면을 전부 끝낸 뒤** P1·P2로 간다.
   시간이 모자라면 P2를 버린다. P0가 하나라도 비면 실패다.

5. **화면 하나씩 저작한다.** 화면 간 의존이 없으면 병렬로 진행해도 된다.
   각 화면마다:

   1. 화면 프레임을 만든다. 이름은 `03`이 정한 것을 **그대로** 쓴다.
   2. `05`의 컴포넌트를 **인스턴스로 배치**한다. 새로 그리지 않는다.
   3. 데이터가 다른 행은 **인스턴스 재사용 + `characters` 오버라이드**
   4. 컴포넌트에 없는 고유 요소만 새로 그린다
   5. `export_shape`로 PNG를 찍어 **눈으로 본다**
   6. 레이아웃 안정 전에 찍히면 빈 영역이 나온다 → **재-export 한 번**
   7. 어긋난 곳을 고친다

   **한 번에 몰아 넣지 않는다.** 작게 쪼개 실행하고 매번 검증한다.
   안 보고 쌓으면 마지막에 전부 어긋나 있다.

6. `03`의 **상태 변형** 표를 처리한다. base 화면을 `clone()`하고 달라지는 것만 얹는다.

7. **마무리 패스를 돈다.**
   - `growType === "auto-height"` 텍스트 전부 `resize` 재계산
   - 프레임 이름이 `03`과 일치하는지 확인
   - 모든 노드 이름이 **의미를 말하는지** 확인 (`Frame 27`이 남아 있으면 고친다)

8. 출력 파일을 쓴다.

## 금지

- **컴포넌트를 무시하고 처음부터 그리지 않는다.** 그러면 ⑤를 분리한 의미가 없다.
- 같은 구조를 **복사·붙여넣기 하지 않는다.** 인스턴스를 쓴다.
- **한 번에 몰아 실행하지 않는다.** PNG로 확인하며 진행한다.
- 컴포넌트 **이름 변경·자식 remove 금지.**
- figma 형식 `fills` 금지. 반투명 스크림 덮기 금지(뒤 보드 `opacity`를 쓴다).
- 토큰 값을 새로 지어내지 않는다. **`04-tokens.md`의 값만 쓴다.**
- 프레임 이름을 임의로 바꾸지 않는다. **`03`이 정한 이름**을 쓴다.
- **특정 PRD 전용 하드코딩 금지.** 화면 이름·개수를 이 파일 지침에 박지 않는다.
- 다른 단계의 출력 파일을 쓰지 않는다.
