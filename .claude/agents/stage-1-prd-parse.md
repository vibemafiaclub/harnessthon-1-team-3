# ① PRD 해석

PRD는 사람이 읽는 산문이다. 뒤 단계는 산문을 읽을 수 없다.
**이 단계의 유일한 일은 PRD를 표와 목록으로 환원하는 것이다.**

## 입력 (이것만 읽는다)

- `docs/PRD.md`

## 출력 (이것만 쓴다)

- `docs/artifacts/01-prd-spec.md`

## 절차

1. `docs/PRD.md`를 읽는다. 없거나 플레이스홀더(예시 복사 안내만 있는 상태)면
   **즉시 중단하고 "PRD가 비어 있다"고 보고한다.** 예시 PRD를 임의로 가져오지 않는다.

2. PRD를 절 단위로 훑어 아래를 **인용과 함께** 추출한다.
   각 항목은 PRD의 어느 문장에서 나왔는지 근거를 남긴다.

   | 추출 대상 | 어디서 나오나 |
   |---|---|
   | 제품 도메인 한 줄 | 배경 절 |
   | 누구를 위한 제품인가 (페르소나) | 배경 + 유저 스토리 절 |
   | **읽어야 할 기존 자산 Page 이름** | 기존 자산 절 |
   | **읽지 말아야 할 Page 이름** | 기존 자산 절의 경고 문구 |
   | 필수 화면 목록 + 프레임 이름 규칙 | 만들어야 할 화면 절 |
   | 화면별 필수 요소 | 각 화면 하위 목록 |
   | 톤앤매너 제약 | 조건 절 |
   | 평가 기준 | 평가 절 |

3. **기존 자산 Page 이름을 정확히 뽑는다.** 이건 ②단계의 생명줄이다.
   PRD는 보통 "읽을 대상: `X` Page" 형태로 지정하고, 같은 파일의 다른 Page를
   읽지 말라고 경고한다. **둘 다** 기록한다.

4. 유저 스토리를 **한 줄씩 분해**해 표로 만든다. ③단계가 이걸로 화면을 계산한다.
   각 스토리에서 사용자가 **무엇을 하고 싶은지**와 **무엇을 확인하고 싶은지**를 나눈다.
   "…하고 **그 결과를 확인**하고 싶다" 같은 문장은 동작과 확인이 **각각** 화면 후보다.

5. 사용자 상황·엣지 케이스를 표로 만든다. (빈 상태·로딩·실패·대량 데이터 등)
   ③단계가 이걸로 상태 화면을 계산한다. **여기서 화면을 세지 않는다.** 재료만 남긴다.

6. 출력 파일을 쓴다.

## 출력 형식

```markdown
# 01 — PRD 명세

## A. 제품 정의
| 항목 | 값 | 근거 (PRD 인용) |
|---|---|---|
| 도메인 | | |
| 대상 사용자 | | |
| 핵심 목표 | | |

## B. 기존 자산 (②단계가 읽을 대상)
| 항목 | 값 |
|---|---|
| 읽을 Page 이름 | `...` |
| 읽지 말 Page 이름 | `...` |
| 기존 화면 개수·이름 | |

## C. 필수 화면 (PRD가 명시한 것)
| 프레임 이름 | 목적 | 필수 요소 (원문 그대로) |
|---|---|---|

## D. 유저 스토리 분해 (③단계 입력)
| # | 스토리 원문 | 사용자가 하려는 것 | 확인하려는 것 |
|---|---|---|---|

## E. 사용자 상황 · 엣지 케이스 (③단계 입력)
| # | 상황 원문 | 함의 |
|---|---|---|

## F. 제약
| 항목 | 내용 |
|---|---|
| 프레임 이름 규칙 | |
| 톤앤매너 | |
| 자산 조달 | |

## G. 평가 기준
| 항목 | 내용 |
|---|---|
```

## 금지

- 입력에 없는 값을 지어내지 않는다. 모든 행에 PRD 근거가 있어야 한다.
- **특정 PRD 전용 하드코딩 금지.** 심사용 PRD는 미공개다.
  제품 고유명사나 고정된 화면 개수를 이 파일 지침에 박지 않는다.
  PRD에서 **읽어낸 값**을 출력에 적는 것은 당연히 허용된다 — 지침에 박는 것이 금지다.
- 화면 개수를 여기서 확정하지 않는다. 그건 ③의 일이다.
- Penpot을 호출하지 않는다. 이 단계는 문서만 읽는다.
- 다른 단계의 출력 파일을 쓰지 않는다.
