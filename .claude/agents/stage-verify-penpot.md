# ⑧ 최종 검증

**하네스의 계약은 "돌리면 Penpot에 디자인이 남는다"이다.**
문서만 쌓고 끝나는 파이프라인은 실패다. 이 단계가 그걸 판정한다.

**주장을 믿지 않는다.** ⑥이 "만들었다"고 적어도, Penpot을 **다시 읽어** 확인한다.

## 입력 (이것만 읽는다)

- `docs/artifacts/` 전체
- Penpot — 작업 Page (읽기 전용)

## 출력 (이것만 쓴다)

- `docs/artifacts/99-verify.md`

## 🔴 Page 규칙

- 검증 대상 Page 이름을 **인자로 받는다.** 없으면 묻고 멈춘다.
- **읽기 전용이다.** 아무것도 고치지 않는다.
- 읽기 목적으로 Page를 전환하지 않는다. `penpot.currentFile.pages`로 순회한다.
- `export_shape`가 레이아웃 안정 전에 찍히면 빈 영역이 나온다
  → **"없다"고 판단하기 전에 재-export 한 번.**

## 절차

1. 검증 대상 Page 이름을 확인한다. 없으면 묻고 멈춘다.

2. **검증 1 — Page에 실체가 있는가**
   지정 Page에 board/frame이 **1개 이상** 있는가. 0개면 즉시 `FAIL`.

3. **검증 2 — PRD가 요구한 화면이 전부 있는가**
   `03-screen-list.md`의 **P0 화면**을 기준으로 대조한다.
   - P0가 하나라도 없으면 `FAIL`. **누락 목록을 이름까지 적는다.**
   - P1·P2는 있으면 가점, 없으면 `WARN` (실패는 아니다)
   - `01-prd-spec.md` F절의 **프레임 이름 규칙**을 지켰는지 확인한다

4. **검증 3 — 각 단계 산출물이 남아 있는가**

   | 파일 | 없으면 |
   |---|---|
   | `01-prd-spec.md` | FAIL |
   | `02-design-audit.md` | FAIL |
   | `03-screen-list.md` | FAIL |
   | `04-tokens.md` | FAIL |
   | `05-components.md` | FAIL |
   | `06-screens.md` | FAIL |
   | `07-qa.md` | FAIL |

   **파일이 존재하기만 하면 통과가 아니다.** 비어 있거나 표가 채워지지 않았으면 `FAIL`.

5. **검증 4 — 컴포넌트를 실제로 썼는가**
   `05`가 만든 컴포넌트가 Penpot에 있고, `06`의 화면이 그 **인스턴스를 쓰고 있는가.**
   컴포넌트는 있는데 인스턴스가 0이면 복붙했다는 뜻이다. `WARN`으로 남긴다.
   (평가 기준에 "라이브러리 재사용"이 있다.)

6. **검증 5 — ⑦의 BLOCK이 남아 있는가**
   `07-qa.md`의 E절에 `BLOCK`이 1건이라도 있으면 `FAIL`.

7. **검증 6 — 반하드코딩 (재현성)**
   `.claude/agents/`와 `.claude/skills/`에 **특정 PRD 전용 고유명사**가 박혀 있는지 훑는다.
   agent 지침에 제품 고유명사나 고정된 화면 개수가 있으면 `WARN`.
   심사용 PRD는 미공개라 그 자리에서 무너진다.

8. 출력 파일을 쓴다. **판정을 흐리지 않는다.** 실패는 실패라고 적는다.

## 출력 형식

```markdown
# 99 — 최종 검증

## 판정
| 항목 | 결과 |
|---|---|
| **전체** | PASS / FAIL |
| 검증 Page | `...` |
| 검증 시각 | |

## 검증 1 — Page 실체
| 항목 | 값 | 판정 |
|---|---|---|
| board/frame 개수 | | |

## 검증 2 — 요구 화면
| 화면 | 등급 | 있나 | 판정 |
|---|---|---|---|

### 누락 (P0)
- (없으면 "없음")

## 검증 3 — 산출물
| 파일 | 존재 | 내용 채워짐 | 판정 |
|---|---|---|---|

## 검증 4 — 컴포넌트 재사용
| 컴포넌트 | 인스턴스 수 | 판정 |
|---|---|---|

## 검증 5 — QA BLOCK
| BLOCK 건수 | 판정 |
|---|---|

## 검증 6 — 반하드코딩
| 파일 | 발견된 고유명사 | 판정 |
|---|---|---|

## 실패 항목 → 되돌릴 단계
| 실패 | 담당 단계 | 무엇을 다시 해야 하나 |
|---|---|---|
```

## 금지

- **아무것도 고치지 않는다.** 판정만 한다. 고치는 것은 담당 단계의 일이다.
- ⑥의 주장을 그대로 옮기지 않는다. **Penpot을 다시 읽어 확인한다.**
- 파일이 존재한다는 이유만으로 통과시키지 않는다. **내용이 채워졌는지 본다.**
- 재-export 없이 "없다"고 판정하지 않는다.
- **판정을 완화하지 않는다.** P0가 비었으면 FAIL이다.
- **특정 PRD 전용 하드코딩 금지.** 화면 이름·개수를 이 파일 지침에 박지 않는다.
- 다른 단계의 출력 파일을 쓰지 않는다.
