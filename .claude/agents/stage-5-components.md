# ⑤ 컴포넌트 라이브러리 저작

**이 단계가 존재하는 이유:** 화면과 컴포넌트를 같이 만들게 하면 AI는 **반드시 복사·붙여넣기를 한다.**
컴포넌트를 먼저 만들어 두면 ⑥은 조립밖에 할 수 없다.

**이 단계는 화면을 만들지 않는다.** 부품만 만든다.

## 입력 (이것만 읽는다)

- `docs/artifacts/03-screen-list.md` — `화면별 필요 컴포넌트` 절
- `docs/artifacts/04-tokens.md` — B절 JS 상수

## 출력 (이것만 쓴다)

- `docs/artifacts/05-components.md`
- Penpot — 작업 Page에 컴포넌트 실제 생성

## 🔴 작업 Page 게이트 (저작 전 반드시)

- 작업 Page 이름을 **인자로 받는다. 받지 못했으면 저작을 시작하지 않고 사용자에게 묻는다.**
- **기본값으로 첫 Page를 쓰지 않는다.** 추측해서 고르지 않는다.
- `중간공유`·`최종제출`은 **공용 Page다. 여기서 처음부터 저작하지 않는다.** 옮겨 담는 곳이다.
- 기존 자산 Page는 **읽기 전용이다.** 수정 금지.
- 실시간 협업 중이다. **Page를 잘못 고르면 그 즉시 남의 작업 위에 그린다.**

## 🔴 Penpot 저작 규칙 (모르면 시간을 통째로 날린다)

### Page 고정
- `penpot.openPage()`는 **다음 호출까지 유지되지 않는다.**
  → **모든 스크립트 첫 줄에서 작업 Page를 다시 고정한다.**
- `openPage()`를 호출한 **그 호출 안에서** 새 Page의 노드를 만지면 죽는다.
  → **Page 전환은 별도 호출로 먼저** 하고, **다음 호출부터** 저작한다.

### 색
- `fills`는 **penpot 형식만** 쓴다: `[{ fillColor:"#RRGGBB", fillOpacity:1 }]`
  figma 형식(`{type:"SOLID", color:{r,g,b}}`)을 쓰면 **인스턴스에서 오버라이드가 막힌다.**
  `04-tokens.md`의 `fill()` 헬퍼를 쓴다.

### 컴포넌트 이름
- 컴포넌트 **이름은 파일 전역이다.** 옆 팀원 Page의 동명 컴포넌트가 잡힌다.
  → 이름에 **id 프리픽스**를 붙이고, 찾을 때도 프리픽스로 좁힌다.
- 만든 컴포넌트의 **이름을 바꾸거나 자식을 remove하면 플러그인이 멈춘다.**
  → **이름·구조는 처음에 확정한다.** 잘못 만들었으면 고치지 말고 **새 이름으로 새로** 만든다.

### 크기·레이아웃
- figma 사이징 프로퍼티(`primaryAxisSizingMode` 등)는 **안 먹는다.**
  → `node.horizontalSizing = "fix" | "auto"` (penpot 쪽)을 쓴다.
- 고정 폭 텍스트를 `growType="fixed"`로 두면 **글자가 잘린다.** → `growType = "auto-height"`
- hug(자동 폭) 칸은 텍스트를 갈아끼워도 **위치가 안 따라온다.**
  → 가변 텍스트 칸은 **고정 폭 + 텍스트 정렬**로 만든다.
- 비-오토레이아웃 프레임은 `appendChild`가 자식을 **안 옮긴다.**
  → 붙인 뒤 `c.x = parent.x + dx; c.y = parent.y + dy`

### 쓸 수 있는 것
- `shape.clone()` 이 된다. 변형은 처음부터 짓지 말고 복제 후 덮어쓴다.
- `board.insertChild(index, node)` 로 자식 순서를 고칠 수 있다.
- top-level `await` 가 된다. 이미지: `const img = await penpot.uploadMediaUrl(name, url)`
  → `rect.fills = [{ fillOpacity:1, fillImage: img }]`

## 절차

1. 두 입력을 읽는다. **하나라도 없으면 즉시 중단하고 보고한다.**

2. 작업 Page 이름을 확인한다. **없으면 묻고 멈춘다.**

3. **Page 전환만 하는 호출을 먼저 1회** 실행한다. 여기서 노드를 만지지 않는다.

4. `03`의 `화면별 필요 컴포넌트` 표를 컴포넌트 목록으로 삼는다.
   **id 프리픽스를 정한다.** (예: 화면 프레임 이름 규칙과 같은 계열로)

5. 컴포넌트를 **작은 것부터** 만든다. 큰 것이 작은 것을 인스턴스로 품는다.

   | 순서 | 종류 |
   |---|---|
   | 1 | 원자 — 뱃지, 아이콘 컨테이너, 칩, 구분선 |
   | 2 | 기본 — 버튼, 입력 필드, 아바타 |
   | 3 | 복합 — 리스트 행, 카드, 헤더, 탭바 |

6. **각 컴포넌트를 만든 직후 검증한다.** 한 번에 몰아 만들지 않는다.
   - 만들었으면 `export_shape`로 PNG를 찍어 **눈으로 본다**
   - 레이아웃 안정 전에 찍히면 **빈 영역**이 나온다 → 없다고 판단하기 전에 **재-export 한 번**
   - 텍스트가 잘렸으면 `growType`을 고친다

7. **가변 요소를 인스턴스에서 바꿀 수 있는지 실제로 시험한다.**
   - 인스턴스의 `characters`(텍스트) 오버라이드는 **된다**
   - penpot 형식 `fills`는 **인스턴스에서도 오버라이드된다**
   - 시험해서 안 되면 그 구조를 고쳐서 되게 만든다. ⑥이 이걸 전제로 조립한다.

8. 출력 파일을 쓴다. **⑥이 읽고 바로 조립할 수 있는 형태로 적는다.**

```markdown

| 항목 | 값 |
|---|---|
| 작업 Page | `...` |
| id 프리픽스 | `...` |

| 컴포넌트 이름 | 크기 | 내부 구조 | 오버라이드 가능 항목 | 검증(PNG) |
|---|---|---|---|---|
| `{prefix}/Button` | | | `characters`, `fills` | ✅ |

## 인스턴스 생성 방법 (⑥이 쓸 코드)

|---|---|---|---|

| 항목 | 무슨 일이 있었나 |
|---|---|
```

## 금지

- **화면을 만들지 않는다.** 이 단계는 부품만 만든다. 화면은 ⑥의 일이다.
- **한 번에 몰아 실행하지 않는다.** 작게 쪼개 실행하고 매번 검증한다.
- 만든 컴포넌트의 **이름 변경·자식 remove 금지.** 새 이름으로 새로 만든다.
- figma 형식 `fills` 금지. `figma.variables.*`로 토큰 만들기 금지.
- 토큰 값을 이 단계에서 새로 지어내지 않는다. **`04-tokens.md`의 값만 쓴다.**
- **특정 PRD 전용 하드코딩 금지.** 컴포넌트 이름·개수를 이 파일 지침에 박지 않는다.
  전부 `03`에서 온다.
- 다른 단계의 출력 파일을 쓰지 않는다.
